## Why this boundary is necessary

V39 proves one prospective mock persistence path, not generic ingestion. Its
receipt must reach terminal consumption without copying the sandbox's fixed
synthetic/provider labels into arbitrary future outputs. Analysis content,
processing provenance, financial interpretation and professional decision remain
different things. Absence of a receipt is not evidence of provider-free execution.

## Implemented composition

- Shared renderer and temporal presentation now reside under services, with no
  sandbox imports. Sandbox compatibility wrappers preserve the previously proven
  closed-workflow disclosures and callable signatures. Those historical labels
  are NOT retroactive V39 receipts. No existing row is altered or re-certified.
- governed_analysis_read exposes the same validated owned envelope plus its exact
  entity/engagement context; the existing reader API remains compatible.
- governed_output accepts only database, authenticated company, analysis UUID and
  requested format. It resolves ownership before reading receipts, obtains the
  integrity-checked V39 record, strict memory projection and governed temporal
  comparison, then composes JSON or XLSX/PDF/PPTX. It accepts no caller-supplied
  pseudonym, provenance label, financial envelope, decision or temporal snapshot.
- Missing receipt: UNATTESTED / origin and provider/transport UNKNOWN, not fabricated
  synthetic truth. Storage errors, corrupt/misbound receipt, incomplete memory or
  invalid terminal composition fail closed. Existing sandbox behavior is separate.
- Verified receipt: execution UUID/time/executor and raw/representation/envelope
  hashes reach all three formats. The no-transport statement is limited to that
  executor, not OS/network monitoring or infrastructure certification. The current
  receipt schema supports ONLY its registered local mock producer; it does not yet
  authorize or describe a generic real-data/provider executor.
- A read/export-only router factory is prepared under routers/governed_output.
  Authentication, admission and database dependencies are mandatory host inputs.
  main.py does NOT import/mount it; no URL or environment flag opens it. A future
  integration must wire actual reviewed auth/admission, not permissive test doubles.
  No new production capability is activated by the factory's existence.

Raw rendering helpers are internal presentation functions, not security capabilities
or independent ownership validators. Only the owned composition is appropriate for
future transport. No claim is made against arbitrary compromised backend Python.
