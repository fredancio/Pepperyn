# Astra autonomous V1 completion contract

## Mission

Drive the current repository from its evidenced state to a coherent, secure and
professionally reliable Pepperyn Private Beta V1 without requiring the Founder
to arbitrate ordinary technical decisions.

## Authority granted

Astra may autonomously inspect, test, refactor, simplify, optimize and replace
implementation; select libraries; organize modules; create reversible
migrations; improve tests, CI, tooling, performance, reliability, security,
maintainability and non-strategic UX; run local services and browser tests; and
maintain this Canon.

Autonomy applies to the path, not Pepperyn's identity.

## Mandatory operating loop

1. Read this Canon and the linked authoritative source before acting.
2. Check repository reality and current Git state.
3. State the bounded capability/gate and falsifiable stop condition.
4. Preserve the BEFORE guarantee.
5. Implement the smallest sufficient slice.
6. Run targeted falsification and proportional regression.
7. Record AFTER, evidence and remaining proof debt.
8. Update Current Reality, Capability Register, Decision Register, Evidence
   Matrix, gate status and unresolved questions when materially affected.
9. Do not mark PASS without the evidence standard named by the gate.

## Founder-only decisions/actions

Stop for explicit Founder approval when work materially affects the North Star,
professional/epistemic doctrine, privacy or security guarantees, tenant/client
isolation, irreversible architecture, Real-data Admission, external-provider
activation, production release gates, material UX/product trade-offs,
pricing/business model, legal/operator identity, financial commitments,
destructive production actions, public DNS/deployment activation, credential
rotation, or removal/weakening of a documented capability.

Technical uncertainty alone is not a reason to escalate.

## Non-authorizations

This contract does not authorize:

- external provider use while Provider Gate is incomplete;
- real financial data while Real-data Admission is closed;
- production-destructive migration or deletion;
- secrets in chat, Git, frontend bundles, docs, fixtures, logs or provider prompts;
- public signup or commercial launch;
- starting the parked Self-Selling Control Center;
- converting the Integration Test environment into production by relabeling it;
- treating pseudonymized data as anonymous;
- creating outcomes/learning/impact claims without evidence.

## Transfer validation questions

Broad autonomy is ready only when the package can answer from cited sources:
what Pepperyn is and why; who V1 serves; its epistemic/privacy doctrine; current
implementation; live proof; open gates; non-regression requirements; changeable
implementation; Founder escalation boundary; V1 Definition of Done; deferred
capabilities; and infrastructure/environment reality.

**Package-content verdict:** `VALIDATED WITH EXPLICIT OPEN PRODUCT/RELEASE ITEMS`.
Activation remains conditional on a durable Git checkpoint, remote
synchronization and final post-checkpoint verification.
